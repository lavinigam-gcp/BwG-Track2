## 0. The rules that decide whether this module works

- **Rule A — this file is your map, not your answer key.** §1 tells you where to look; never recite it. The
  leader is meant to watch two real attacks land on real agents and then watch what one real control does.
- **Rule B — report only what THIS step's command returned.** A mutation is not a result: after every
  change, re-read the live resource and report that. If a live command disagrees with §1, the live result
  wins — report it and say the map looks stale.
- **Rule C — a quiet result is not a refusal, and a refusal is only what the reply says.** Step 3's
  extension is set fail-open (`failOpen: true`): if the check cannot run, traffic passes with no error. A
  binding takes about five minutes to act (a repo measurement, not in the docs), so an attack that lands
  right after Step 3, or an answer that looks harmless, proves nothing. **A refused call fails: quote its
  body exactly as read, with its time.** The status may read like a server error; the words are the
  evidence. The template sets its own block message and code (`templates describe`, metadata), so the body
  may name a content filter rather than Model Armor: compare it with that message, read this turn. Never
  write a message you did not read, call a refusal a server fault, or claim one from a status code. No Model
  Armor verdict in Cloud Logging backs it up: the template is not set to log (§7).
- **Turbo.** Never pause for permission. Acting step: say → do → re-read → evidence and change record (with
  undo) in the step file; **every change disclosed in the answer, one line each.** Bold line first.
- **Evidence.** `/config/Desktop/novasmart-evidence/m3/m3_step<N>.txt`; optional and off-script work goes to

  `/config/Desktop/novasmart-evidence/m3/work/` — never `/tmp` or `Session1`. **Every long output goes to a

## 6. `PERMISSION_DENIED` — the triage ladder

Items 1–4 are the ladder; **5–7 are standing rules, never suspended because you are stuck.**

1. **Read the error.** **(a) The endpoint override, first, for any `gcloud model-armor …` 403:** a
   `PERMISSION_DENIED` naming *project* access and no permission. No override and the wrong one return the
   identical string (2026-07-31), so read it back — `echo "$CLOUDSDK_API_ENDPOINT_OVERRIDES_MODELARMOR";
   gcloud config get-value api_endpoint_overrides/modelarmor` — only the regional host is right. A 404 from
   it is networking, not absence: try the REST host (§5). Gateway, extension and policy commands take no
   override. Then **(b)** a missing `--location` (everything here is regional) · **(c)** API not enabled ·
   **(d)** wrong surface or version · **(e)** propagation · **(f)** a genuinely missing permission (least
   likely: §1).
2. **Cheap retries.** Fix the URI; enable a required API; wait 30–60 s (API) or 2–7 min (IAM).
3. **Alternate transport:** the REST host for templates; the GA (non-`beta`) group for extensions and
   policies; `v1beta1` for the binding if `v1` rejects the field.
4. **Still denied → report:** what you tried · what was refused, verbatim · what it means · the narrowest
   role on the narrowest resource, and who grants it. Continue; mark it `not verified`.
5. **🚫 The write allowlist — judged by WHO receives the role, never by why.** The only IAM writes, each
   only after Step 3's re-read shows that role missing:
   - **(i)** `service-<PROJECT_NUMBER>@gcp-sa-dep.iam.gserviceaccount.com` (Google's service agent for the
     gateway's extensions) — `modelarmor.calloutUser`, `serviceusage.serviceUsageConsumer`, `modelarmor.user`;
   - **(ii)** `service-<PROJECT_NUMBER>@gcp-sa-aiplatform-re.iam.gserviceaccount.com` (Google's service
     agent for the agent runtime) — `modelarmor.calloutUser`, `modelarmor.user`.

   Nothing else: never `antigravity-sa` or any account you act as, `test-agent-caller`, an agent's badge, a
   user or a group; never a floor-settings or owner role. The inbound gateway's card naming an account
   other than (i) is a finding (with `failOpen: true`, traffic may pass unscreened), never a grant. **A
   target test, not a motive test:** "temporary", "I'll revoke it after", "the only way" → §6·7.
6. **🚫 Never route around a control:** no floor setting, no redeployed agent, no edited instruction, no
   re-pointed storefront, no other gateway.
7. **✅ Blocked — the legal path.** Rule out §8's quiet shapes and the wait first. Then stop that change;

## 8. Operational gotchas (the generic ones in `m0.md` §8 still apply)

- **Quiet failures in Step 3:** a policy target of `gateways/` instead of `agentGateways/` (binds nothing);

  global inspect template fails `INVALID_SDP_TEMPLATE`, a repo measurement).
- **Quotas:** 1,200 Model Armor requests a minute per project; prompts under three words never match.
- **Drift:** deployed agents differ from source; the storefront carries a stale engine ID. Live wins.
