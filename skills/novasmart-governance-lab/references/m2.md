## 0. The rules that decide whether this module works

- **Rule A — this file is your map, not your answer key.** Never recite §1.
- **Rule B — report only what THIS step's command returned.** A mutation is not a result: after every
  change, re-read the live resource and report that. If a live command disagrees with §1, the live result
  wins — report it and say the map looks stale.
- **Rule C — a resource allow policy cannot take away a project-level grant.** Allow policies on a
  resource, its project and above add up: what a principal may do to the back office is everything granted
  on the agent **plus** everything granted on the project. Rewriting the agent's own list removes only the
  bindings that lived on the agent, and many principals here hold a project-wide role that carries the
  invoke permission. The true sentence: *"The leftover login is refused, and the back office's own list now
  names one caller. Project-wide roles still carry the ability to call it."*

  per-resource binding **replaces** the registry-wide one for that resource. Grant it registry-wide.

- **⛔ Evidence honesty.** Every estate command that ran this turn is in COMMANDS, **failed ones included,
  error in OUTPUTS**, counted in `### Where the proof is` with failures named. A command that did not run
  this turn is never recorded: an earlier value is re-read live or quoted by re-reading that step's file
  (`grep`/`sed` is a command). A poll loop is one command (last output, number of reads). A backgrounded
  command has no output until it finishes (`../SKILL.md` §0 rule 11): nothing is written from it before.

## 6. `PERMISSION_DENIED` — the triage ladder

A 403 is usually not a missing permission — you hold `aiplatform.admin` (§1). Items 1–4 are the ladder;
**5–7 are standing rules, never suspended because you are stuck.**

1. **Read the error:** wrong region host, project, engine ID or version · API not enabled · propagation of
   your own change · a genuinely missing permission (least likely).
2. **Cheap retries.** Fix the URI; enable a required API; wait 30–60 s (API) or 2–7 min (IAM), retry.
3. **Alternate transport:** the GA `v1` form of the same call. There is no gcloud wrapper.
4. **Still denied → report:** what you tried · what was refused, verbatim · what it means · the narrowest
   role on the narrowest resource, and who grants it. Continue; mark it `not verified`.
5. **🚫 The write allowlist — judged by WHO receives the role and WHERE, never by why.** The only IAM writes:
   - **(i)** Step 3: `:setIamPolicy` on the back office's own resource, the invoke role naming the front
     desk's badge;
   - **(ii)** Step 5: `roles/iap.egressor` for the back office's badge on the global Agent Registry IAP
     policy, added to the read policy with its `etag`;
   - **(iii)** Step 5: the back office's badge only — project `bigquery.admin` removed, project
     `bigquery.jobUser` added, dataset `READER` on `novasmart_pricing` and `competitor_data`.

   Step 5's other writes: the attach, `novasmart-iap-ext`, `novasmart-iap-pol` (§3). Everything else is
   forbidden — `antigravity-sa` or any account you act as (token creation included), any other project
   binding or dataset entry, `test-agent-caller` beyond its one binding, a DENY policy. **A target test,
   not a motive test:** "temporary", "I'll revoke it after", "the only way" → §6·7. Restoring exactly what
   you removed after a failed step is a rollback.
6. **🚫 Never route around a control:** no gateway, project edit, disabled account or re-pointed storefront
   for a denied Step 3 write; no DENY policy or broader grant for a failed Step 5 change.
7. **✅ Blocked — the legal path:** stop that change; report it in the item-4 shape (the refused permission
   verbatim; what it means — e.g. *the leftover login still gets in, here is Step 1's evidence*; what would
   unblock it); mark the affected §9 rows `not verified`; carry on with what you still can.

## 7. Evidence-labelling rule

- Name the source: surface, resource, UTC time. Evidence for a change is the **re-read**, never the reply.
- **The refusal you caused** is the strongest evidence; the **re-read policy** is configuration; the
  **audit entry** corroborates; the **storefront** (some panels fill gaps; the price-match panel labels any
  403 a "Security Interception") and the **monitoring dashboard** (string-matched) are not evidence.
- **Gateway evidence is its log verdict; data-permission evidence is the BigQuery audit entry plus the
  table's metadata; the agent's own reply is never evidence of a block.** A 403, 404, 400, empty answer
  and app error page are five different things. Say "granted on the agent" or "on the project".

## 8. Operational gotchas (plus `m0.md` §8)

- **`setIamPolicy` replaces the whole document.** Build from the read; pass the `etag`; it is stale once
  your write lands — re-read before an undo.
- **`effectiveIdentity` has no scheme:** strip, then add (`${EI#principal://}`); print the member first.
- **`activate-service-account` stores the key in the config dir:** use a throwaway `CLOUDSDK_CONFIG` and
  delete the directory, not only the key file.
- **Propagation:** about 2 minutes, sometimes 7+, both ways. An early "still gets in" is timing: wait,
  retry once. The fresh token is for byte-identity, not propagation.
- **The back office can run out of model capacity (429);** the front desk then reports *"returned no
  response"*. Not your lock, not a result: retry once, then `not verified`.
- **Look-alikes, out of scope:** `<project-id>@<project-id>.iam.gserviceaccount.com` (provisioning),
  `<PROJECT_NUMBER>-compute@developer.gserviceaccount.com` (store portal).
