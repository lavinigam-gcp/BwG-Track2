## 0. The rules that decide whether this module works

- **Rule A — this file is your map, not your answer key.** §1's outcomes are what the dataset *expects*,
  not what the agent *did*. You find out what it did by running it.
- **Rule B — report only what THIS run returned.** If a live result disagrees with §1, the live result
  wins: report it and say the map looks stale.
- **Rule C — never fabricate, infer, round up or smooth a result.** No total not counted from per-case
  results; no `matched` without the actual reply; no result while a job is unfinished; no "essentially
  all". **A partial run reported honestly is a good outcome; an invented total is the worst one.**
- **Rule D — no score, anywhere.** No pass rate, percentage, `n / 5`, delta or predicted result, in any
  step, picture or close. The total is accounting (AR-2), never a grade. "Scorecard" in this module means
  the evaluation results table: **M4 has no governance scorecard; never run `update_scorecard.py`.**
- **AR-1 · Name the judge you built, or say there was none.** A judge name goes on screen only if this
  turn's entry holds the call that built or configured it and the call that ran it. **The judge model is
  never the agent's own model**: read the agent's model from its record (§5) and name both. A model name
  from the agent's own reply is the agent's, not a judge. If no judge model ran, head the column
  **"my reading — no judge ran"** and say that sentence in the prose: a labelled fallback, never the plan.
- **AR-2 · One denominator, fixed before the first case runs.** Write `N` when you read the set; report
  every total as **`n matched · f did not · u not run`, with `n + f + u = N`**. A new set (Step 2) gets a
  new `N`, announced, never blended. Never `n passed of m run`. ⛔ "complete" never appears while `u > 0`
  or a job is pending, and a `not run` case never migrates into `f`.
- **AR-3 · A near-miss needs a reply to point at.** It is the right outcome reached by faulty reasoning:
  quote the agent's words and name the faulty step in them. A case with no reply is `not run`; a case
  refused before the agent saw it is a refusal (SEAM), never a near-miss.
- **AR-4 · A caption is a claim.** Every element of a picture traces to a command run this turn; anything
  else is marked **unknown** or left out, or the caption is narrowed (`../SKILL.md` §3b).
- **AR-5 · Banned verdict words.** Search your draft for *secure · safe · locked down · fully protected ·
  production-ready · complete · risk eliminated · all clear · fixed*. Each hit is a quotation, an explicit
  prohibition, or deleted.
- **SEAM · A refusal has two possible authors.** If the Price Match agent's record shows a screening
  gateway attached (§5, read this turn), its content screen sits on `:streamQuery`, the endpoint the
  deployed run uses, and a refusal may come from the screen or the agent. The tell measured in M3 is an
  **HTTP 500** whose body reads `Model Armor: Prompt violates content security configurations` (not yet
  observed in an M4 run); a blocked *reply* is also possible, and an SDK path may retry and record an
  error string. **Quote the message, never the bare status**, report what the run recorded, and label the
  row **answered by the screen — the agent was never asked**, whichever verdict it carries. No gateway
  attached → no screen exists: never mention one as present. The local copy has no screen at all.
- **Evidence (`../SKILL.md` §3g).** `/config/Desktop/novasmart-evidence/m4/m4_step<N>.txt`; optional,
  promptless and off-script work goes to `m4/m4_other.txt`. Step 1's working files go in
  `/config/Desktop/novasmart-evidence/m4/work/`; the local copy, its case file and results in
  `/config/Desktop/novasmart-evidence/m4/local/` — never `/tmp`, never `Session1`.
- **⛔ Evidence honesty.** COMMANDS copies each block exactly as it ran (`$(date …)`, loops and heredocs
  stay as written); failed commands are recorded with their exit code and counted. **Long outputs go to
  files; checkpoints (UTC times, statuses, hashes, counts) go to a small file you `cat` back before the
  entry** — `run_command` keeps only the last ~8 KB, and a value you did not see is never filled in from
  timing or memory. `Written` is printed by `date -u`, never typed. A background command has no output
  until "finished with result" arrives (`../SKILL.md` §0 rule 11).
- **Change record.** Every M4 entry prints `(nothing changed in the estate in this step)`. Step 4 adds two
  lines naming the local file it edited and its backup, labelled *a file in a folder on this workstation,
  not the estate*. **No `Undo:` line, and no undo clause in `### Where the proof is`.**
- **Identifiers on screen:** short names — *the Price Match agent*, *the shipped scenario set*, *a folder
  on this workstation*. No `projects/`, `principal://`, `roles/`, `@`, paths or bucket URLs in the answer
  or a picture; they go in the file.
- **Numbering** matches the M4 Instructions tab, which restarts at 1: **Step 1** Run the evaluation and
  read the scorecard · **Step 2** Build a tougher set and run it · **Step 3** See the fix before you make
  it · **Step 4** Make the change and see what is actually running · **Decide whether to launch** and
  **What you built** (no number, no prompt) · **Step 5** Show what you measured. Say the name.
- **Match declaration.** Block 0's location line (*"This is Step N of Module 4, <title>."*) is the match.
